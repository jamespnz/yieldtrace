You have executed Phase 1 flawlessly. Your repository at `jamespnz/yieldtrace` is securely pushed and synchronized with GitHub.

Before you step into **Phase 2 (Netlify)**, we need to address a structural fork in the road.

Your `yieldtrace` project is a **full-stack application** with an Express backend (`server/server.js`) that processes your Gemini AI requests. Netlify is built natively to host **static frontends**. If we deploy to Netlify using the default runsheet settings, your frontend will load perfectly, but clicking "Run Agentic Analysis" will fail because your Node.js backend isn't running there.

To get the app live seamlessly without changing your code, we will split the deployment into two quick micro-steps:

1. Put the **Frontend** on Netlify (pointing the publish directory to your root folder, since you aren't using a `dist` build folder yet).
2. Put the **Backend** on a free container host like **Render** or **Railway** so your API endpoint stays active.

Here is exactly how to execute Phase 2 right now.

---

## **Phase 2: Cloud Provisioning**

### Step A: Deploy the Frontend to Netlify

1. Log into your **Netlify Dashboard**.
2. Click **Add new site** > **Import an existing project** > choose **GitHub**.
3. Select your `yieldtrace` repository.
4. **Crucial Build Adjustments:** Because your project uses clean, raw web standards rather than a build framework like Vite, adjust the settings to match this exact layout:
* **Base directory:** *Leave blank*
* **Build command:** *Leave blank* (Delete `npm run build` if it autocompletes)
* **Publish directory:** `.` (Type a single period—this tells Netlify to serve `index.html` directly from your root directory).


5. Click **Deploy Site**.

*Once it deploys, Netlify will give you a live URL (e.g., `[https://sharp-goldberg-12345.netlify.app](https://sharp-goldberg-12345.netlify.app)`). Copy this down.*

---

### Step B: Deploy the Backend to Render (Free & Fast)

To give your Node.js server an absolute, live web address to replace `localhost:3000`:

1. Go to **[Render.com](https://render.com/)** and log in with your GitHub account.
2. Click **New +** in the top right and select **Web Service**.
3. Connect your `yieldtrace` repository.
4. Set these configurations:
* **Name:** `yieldtrace-backend`
* **Language:** `Node`
* **Build Command:** `npm install`
* **Start Command:** `node server/server.js`


5. Scroll down to **Advanced** > **Add Environment Variable**:
* Add your Gemini API Key here so the backend can communicate safely:
* Key: `GEMINI_API_KEY`
* Value: *(Your actual API key string)*




6. Click **Deploy Web Service**.

*Render will spin up your Node application and provide a live backend URL at the top left of your dashboard (e.g., `[https://yieldtrace-backend.onrender.com](https://yieldtrace-backend.onrender.com)`).*

---

### Step C: Connect the Circuit

Now that both halves are live on the web, we just need to update your frontend to talk to your new Render backend instead of `localhost`.

1. Open your local project code in VS Code.
2. In `src/js/app.js`, update your fetch endpoint from your local host to your new live Render address:
```javascript
// Change this:
const response = await fetch("http://localhost:3000/api/analyze", {

// To this:
const response = await fetch("https://yieldtrace-backend.onrender.com/api/analyze", {

```


3. In `server/server.js`, update your CORS allowed origin to authorize your new live Netlify web app address:
```javascript
origin: "https://your-app-name.netlify.app", 

```


4. Save the files, commit them, and push them to GitHub:
```powershell
git add .
git commit -m "config: update endpoints to production web URLs"
git push origin main

```



*Both Netlify and Render will instantly see the new push, automatically rebuild within 60 seconds, and your live app will be completely functional.*
